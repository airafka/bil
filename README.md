## Правила работы

- Много незакоммиченных изменений: сохранять их, не делать reset/checkout/clean поверх работы пользователя.
- Без отдельного запроса не делать commit/push, не очищать БД, не удалять Docker volume.
- Перед миграциями и изменением существующих данных создавать проверенную резервную копию.
- Сначала проверять изменения данных на копии, затем обновлять локальную сборку и проверять health/API.
- Не запускать повторно одноразовые seed/cleanup/renumber-сценарии без задачи.
- Использовать существующие поля MVP и текущую стандартизацию. Не добавлять вымышленные исторические даты, тарифы или реквизиты.
- Интеграции TOS, Datareon, 1С, ЭТРАН не реализованы. Локальные накладные не означают подключение к ЭТРАН.
- После доработки обновлять текущие документы, избегая противоречивых дополнений; история сохраняется отдельно.
