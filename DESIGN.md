# Стандарт интерфейса MVP

Актуализировано **03.11.2026**. Применяется к созданию, просмотру и редактированию. История макетов и прежних решений — в [архиве](docs/history/2026-11-03-handoff/DESIGN.md); старые размеры/исключения там не отменяют этот стандарт.

## Макеты и принцип реализации

- [Поставка — Figma](https://www.figma.com/design/H9pcFGKBkZcIKXPH3O9W5H/?node-id=1838-335358): файл H9pcFGKBkZcIKXPH3O9W5H, исходный узел1838:335358. Экраны реестра6336:19827, создания5911:60712, просмотра1838:515322 ранее использовались как образцы.
- [Справочники, услуги, настройки — Figma](https://www.figma.com/design/mt2hmgrt0oXux4GR32mlHj/?node-id=1-2): раздел, подписанный в макете как заявка на услугу, для соответствующего сценария MVP называется «Смена собственника КТК».
- Использовать существующие поля MVP. Отсутствующие сведения не изображать заполненными. Архивы основной системы — справочник, не инструкция добавить всё сразу.

## Структура карточки

- Светлая рабочая область, заголовок страницы и действия сверху справа.
- Белый `form-workspace` объединяет вкладки и содержание, с одинаковыми отступами, в том числе в комплексной услуге.
- Основное: «Основная информация», затем предметные группы; просмотр показывает текст, а не заблокированные поля.
- На широком экране реквизиты в двух колонках, на узком — в одной. Подписи не накладываются на значения.
- В поставке и вывозе одинаковые группы/геометрия. У вывоза грузополучатель вместо грузоотправителя и нет собственника КТК по умолчанию.
- Связанные документы показываются полями с гиперссылкой **на номер**: Заявка на услугу, Исходная поставка, Исходный вывоз, Заявка на возврат, Рейс. Не заменять номер текстом «Открыть…».
- Активная вкладка белая с рамкой, остальные на светлой подложке. При нехватке места вкладки прокручиваются по горизонтали.

## Кнопки и действия

- Переходы, Сохранить, Отмена и Закрыть располагаются сверху. Не дублировать нижние панели сохранения/переходов.
- Редактирование — иконка карандаша с aria-label/title; не текстовая кнопка «Изменить».
- Закрытие — крестик. В боковой форме рейса40×40px, одинаковой высоты с основной кнопкой.
- Кнопки создания реестров/тарифов: **+ Создать**, общий `create-action-button`.
- Стандартная высота основных действий40px, табличных30px. Кнопки не должны растягиваться из-за наследования стилей другой формы.
- Удаление — действие строки реестра через RowActions, не верх карточки.
- Не добавлять кнопки «К справочнику», «Обновить», «Снять выбор» и пояснения о выбранной строке, если задача явно не требует.
- Двойной клик строки открывает карточку там, где она есть; интерактивные элементы строки не должны вызывать побочную навигацию. Общий компонент `RecordRow`.

## Таблицы

Источник стандарта — **`frontend/src/table-system.css`, подключён последним**.

| Элемент | Размер |
| --- | ---: |
| Обычная строка / шапка | 36px |
| Поле или кнопка внутри строки | 30px |
| Индекс / служебная колонка действий | 44px |
| Основной текст / шапка | 14px /13px |

Белые строки, светло-синяя шапка, тонкие границы, единые отступы. Многострочный состав может занимать больше одной строки; не скрывать содержимое ради жёсткой высоты.

Геометрия колонок должна сохраняться между просмотром и редактированием. Широкая таблица прокручивается внутри контейнера, не растягивает страницу. В услугах таблицы оформляются как табличная часть поставки: рамка, скругление, вертикальные разделители, белый рабочий блок. Не добавлять повторные подписи «Тарифы по договорам», «Созданные заявки на вывоз» над таблицами.

Реестр поставок/вывозов: Номер заявки → Клиент → Дата и время из заявки → Площадка → Вид транспорта → Рейс (ссылка) → Услуга (номер комплексной заявки, ссылка) → Комментарий → Статус; служебная колонка отдельно.

## Выбор и поля

- Общие `UiInput`, `UiSelect`, `UiTextarea`, `UiMultiSelect` из FormControls.
- Отмеченный checkbox синий с белой галочкой, включая readonly/disabled; не серый системный. Checkbox16×16px, не растягивать как текстовое поле.
- Выбор/снятие — checkbox. Выбор всех — checkbox шапки таблицы, а не отдельная кнопка.
- В выборе рейса отмечается **только checkbox**, без заливки выбранной строки.
- Все одиночные выпадающие списки имеют стиль поля клиента. Пустой первоначальный option скрыт: нет видимых строк «Выбрать…»/«Выберите…».
- Грузоотправитель/грузополучатель — UiSelect из client во всех формах, включая таблицы комплексной заявки. Не свободный текст.
- Множественный КТК — dropdown со стандартными чекбоксами. Выбранные номера внутри поля одной строкой, длинное значение с многоточием, не чипы под полем.
- Поля счета имеют ширину как в создании поставки, не на весь экран. Обязательные клиент/договор/период и необязательный КТК следуют друг за другом.
- Не добавлять поиск/фильтры/счётчики над табличной частью без предметной необходимости. Существующие нужные механизмы согласовывать с задачей, не удалять автоматически из всего приложения.

## Уведомления

Общие `NotificationProvider`/`Notification`: ошибки, предупреждения и успех — сверху справа. Не вставлять баннеры и служебные пояснения под таблицами. Статический текст вроде «Выбран рейс…», «Выбор сохраняется…» или «Состав и суммы сохранены в черновике…» не нужен.

Ошибки должны объяснять, какое поле/заявку исправить; не прятать бизнес-ошибку и не выводить stack trace пользователю.

## Рейсы

Выбор: checkbox, Рейс (номер), Заявки (связанные номера), Дата и время, Комментарий; без кнопки обновления и отдельной строки выбранного рейса.

Просмотр: `RouteInformation`, группы Основная информация, Логистика (только авто), Дополнительно. Если рейс не выбран, в **просмотре** остаются подписи с пустыми значениями. В форме выбора этот блок не показывать. Статус только в основной информации, не возле кнопки подтверждения.

Интервал даты — один час UTC+3, через полночь показывать дату окончания. Для ЖД подпись зависит от направления. Редактирование отдельного рейса — вкладки Основное и Заявки.

Создание из транспортной/комплексной заявки — боковая форма. `AppOverlay`/createPortal помещает её в `#app-overlay-root` вне таблиц и родительских form. `route-dialog.css`: одна колонка полей, естественная высота секций, прокрутка тела, действия справа. В боковой форме OrderRouteCell подпись слева (220px), поле справа; до480px подпись над полем. Не допускать наследования tabular nowrap/30px или сжатия блока логистики до наложения с комментарием.

`RouteLogisticsFields`: выбираются перевозчик/водитель/ТС, остальные реквизиты readonly из справочников. Прицеп показывается стандартным checkbox и номером. Эти поля уже реализованы; старое утверждение об отсутствии справочников неактуально.

## Накладные и состав услуги

- Выбор накладных встроен в форму: checkbox, номер, дата создания в ЭТРАН, вид отправки, статус. Без поиска, фильтров, троеточия действий, «Снять выбор» и длинного описания совместимости.
- Старую неизвестную дату показывать «Не указана».
- Список выбора накладных — плоская таблица; вагоны/груз сгруппированы по накладным; КТК — накладная→вагон→КТК. В создании и просмотре одинаковая иерархия, без серого выделения вагонов.
- КТК для формирования вывозов и уже созданные заявки — отдельные блоки.
- Таблицы вывозов/возвратов содержат дату направления и контрагента. Карандаш включает редактирование DRAFT-строк, единые Сохранить/Отмена сверху, значения сохраняются при смене вкладок.
- Блок начислений отсутствует, пока записей нет (в том числе при первичной загрузке). Нулевой размер суммы у существующего начисления не означает пустой блок.

## Услуги, тарифы, счета, смена собственника

Карточка каталога услуги: Основное по стандарту транспортной заявки, вкладка Тарифы с + Создать справа. Active в строках только для просмотра; менять в форме тарифа. Общая карточка тарифа без списков счетов/услуг, относящихся к отдельному начислению.

Счёт называется «Счёт №…» независимо от DRAFT. Карандаш для черновика, «Оплачен» сверху, оплаченный не редактируется. Выбор начислений через таблицу; лишние пояснения/массовые кнопки над ней удалены.

Смена собственника: только Черновик/Выполнено, действие «Подтвердить», карандаш, выбор КТК обязателен. Названия из Figma не подменяют название раздела MVP.

Активный раздел бокового меню — светло-голубая заливка по образцу пользователя. Статусы КТК без декоративных точек.

## Создание и просмотр накладных

Форма создания накладной и раскрытие её состава в реестре используют иерархические таблицы в стиле поставки КП-ЖД: накладная → вагоны на вкладке «Вагоны», накладная → вагон → КТК на вкладке «КТК», накладная → строки груза на вкладке «Груз». Группы белые, со стандартными шевронами. Массы и ЗПУ КТК вводятся в одной строке; отдельные карточки вагонов и чипы номеров не используются. Просмотр показывает текст. Номер накладной до автоматического присвоения обозначается «Новая накладная». Действия добавления КТК рядом с номером вагона, обычные строки36px и поля30px, горизонтальная прокрутка внутри таблицы. Основные реквизиты — две колонки, на узком экране одна. Реализация: WaybillDraftComposition, WaybillHierarchyView и общий WaybillCompositionTable.
