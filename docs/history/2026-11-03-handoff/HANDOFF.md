## Бизнес-правила заявок и услуг

- Статусы: `DRAFT` — «Черновик», `CONFIRMED` — «Подтверждено», `COMPLETED` — «Выполнено».
- Черновик означает, что заявка создана. Подтверждение означает отправку во внешнюю систему. В дальнейшем выполнение должна устанавливать смежная система; в MVP статус меняют вручную.
- Заявка на услугу объединяет два процесса. В интерфейсе показывать **наименования из справочника**, без «Услуга 1/2» и буквенных префиксов.
- Первый процесс: первоначальная поставка и последующий вывоз КТК. Услуга выполнена по КТК только после выполнения заявки на его вывоз. Принятым КТК считается после выполнения первоначальной поставки.
- Второй процесс: возвратная поставка, созданная на основании вывоза. Выполнение определяется выполнением соответствующей заявки на поставку.
- Для КТК «Стандартный 20» заявки на вывоз создаются через выбор КТК; нельзя считать, что вывоз автоматически оформлен на каждый КТК.
- Количество КТК и количество заявок — разные показатели. В первоначальной поставке всегда одна заявка; отдельное количество заявок нужно показывать для вывоза и возвратной поставки.

## Собственник КТК независимо от клиента — уточнение 2026-11-02

Обычный client_id заявки на поставку/вывоз не определяет собственника регистра. При создании поставки defaultContainerOwnerId обязателен и выбирается независимо от клиента; неуказанный собственник строки подставляется из этого поля, явный собственник строки имеет приоритет. В черновике можно менять собственника отдельного КТК; изменение общего собственника по умолчанию по ранее принятому правилу обновляет все строки. Смена клиента/транспорта формы не заменяет отдельно выбранного собственника. Старые сохранённые владельцы и данные не переписываются.

При подтверждении поставки container_owner.client_id получает собственника соответствующей строки receiving_order_container (статус EXPECTED). UNLOAD_FINISH переводит КТК в ON_TERMINAL с сохранением собственника регистра. CHANGE_OWNER изменяет собственника регистра; DRAFT/CONFIRMED вывозы получают актуального собственника из container_owner по container_id. Изменение регистра синхронизирует owner_container_id активных вывозов в той же транзакции. Завершённый вывоз хранит собственника на момент LOAD_FINISH и не меняется задним числом.

По отдельному уточнению пользователя возврат допускает ручной выбор собственника. При создании собственник каждого КТК копируется из вывоза: для активного вывоза это актуальный регистр, для завершённого — сохранённый собственник на момент вывоза. Общий default возврата устанавливается по первому КТК; у всех строк сохраняются их собственные значения. Ручное изменение владельца в черновике возврата разрешено; при подтверждении такой возврат регистрирует выбранного владельца. Поэтому смена владельца через явно отредактированную входящую поставку допустима по требованию пользователя; дефектом A2 была именно непреднамеренная подстановка клиента.

## Подтверждение транспортных заявок через рейс · 03.11.2026
