# Единый стандарт frontend

Актуально: 06.11.2026. Применяется к новым доработкам и существующим страницам bil-next. Этот документ заменяет прежние указания о превращении таблиц в карточки на узких экранах.

## Размеры и компоненты

| Элемент | Стандарт |
| --- | --- |
| Поле и основная/второстепенная кнопка | 40 px, текст 14/20 px |
| Поле/кнопка в таблице | 30 px |
| Строка таблицы | от 36 px, растёт только по содержимому |
| Заголовок таблицы | 13/20 px, фон #eef4ff |
| Статус | от 24 px, текст 12/18 px |
| Флажок | 16 px |
| Скругление поля/кнопки | 5 px |
| Отступ между элементами | 8 px; между разделами 16 px |
| Подпись поля | слева, поле справа; обычная колонка 180 px |

Длинные выбранные значения могут увеличивать высоту списка: текст не обрезать. В формах на телефоне подписи располагаются сверху. Для длинных подписей рейса используется колонка 220 px, для коротких подписей возврата — 100 px. Смысловые цвета статусов сохраняются.

## Источники стиля

- frontend/src/ui-kit-tokens.css — единые размеры и цвета полей.
- frontend/src/components/FormControls.tsx — UiInput, UiSelect, UiTextarea, UiMultiSelect. Использовать их вместо новых вариантов полей.
- frontend/src/ui-system.css — окончательные общие размеры, подключается последним. Страничные стили задают расположение, а не новые размеры компонентов.
- Кнопки используют общие primary-button, secondary-button, outline-action-button, icon-button, close-button; иконки — ActionIcon. Не вводить локальные варианты высоты, шрифта и скругления.
- frontend/src/table-system.css и responsive-tables.css — строки, ячейки, рамка и прокрутка.
- useResponsiveTables + tableGeometry — единый расчёт ширины без зависимости от режима редактирования.
- /ui-kit — интерактивные образцы на реальных компонентах; страница не создаёт документов и не записывает данные.

## Таблицы

Сохранять нативные table/thead/tbody, colSpan/rowSpan и иерархию накладная → вагон → КТК на любой ширине. Выпадающий список собственника находится в своей ячейке. На узком экране прокручивается только рамка таблицы; страница не расширяется. Не превращать строки в карточки.

Ширины колонок задавать числовыми значениями colgroup: это минимальные ширины и пропорции распределения свободного места. Служебные колонки — 44 px. Если сумма ширин меньше рамки, свободное место распределяется между колонками данных, без пустой полосы справа. Если больше — горизонтальная прокрутка. Не подменять размеры измерениями уже отрисованных ячеек; редактирование не меняет структуру таблицы. Короткие действия, включая «Создать рейс», в одну строку. Рамка с прокруткой доступна с клавиатуры.

Необязательные фильтры и поиск в системе не показывать. Клиент, договор, период счёта, станции и плательщик накладной остаются обязательными реквизитами, определяющими состав документа. История собственников показывается полностью, включая резервирования.

## Проверка доработок

Проверять обычное, недоступное, ошибочное состояния и фокус; таблицы с данными и пустым результатом. Проверять 1440/1024/640/360/320 px, раскрытие иерархии, выбор в строке, вкладки и боковые панели. Длинные значения читаемы, обязательность не отделена от подписи, кнопки не переносят короткие действия. Проверки интерфейса на рабочей БД — без сохранения; изменяющие тесты только на отдельной тестовой БД. Сборка frontend включает ESLint, Vitest и TypeScript/Vite.

Для начислений и строк счёта задавать явные пропорции: короткие дата/номер/договор/сумма занимают компактные колонки, названию услуги отводится основная ширина. Не назначать nowrap всем ячейкам таблицы или номерам столбцов: длинные значения переносятся внутри своей ячейки. Проверка текста должна измерять границы отдельных строк, а не только общую ширину таблицы; проверять также эффективную ширину и масштаб90%.
